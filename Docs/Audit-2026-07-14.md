审核启动：2026-07-14

实现/文档快照：2026-07-16
状态：重构实现已覆盖全局 UI、领域一致性、同步、安全与性能；最终冻结工作树验证仍在收口

本文把“审核起点发现”“已实施修复”“已有定向证据”和“最终发行门禁”分开。起点的 P0/P1 是 baseline finding，不是当前仍未处理的 blocker；最终测试/构建/截图/trace 没有取得证据前也不会被写成通过。

## 1. 执行摘要

本轮不是单点修补。审核覆盖主应用、SwiftData/CloudKit、App Intents、Live Activity、Widget、Watch、三语言资源、测试与文档，并允许 UI、操作流程、代码和同步结构发生 breaking change。

主要结果：

- iPhone 改为系统五标签；iPad/macOS 使用原生 split navigation；macOS 使用一个主 `Window`，Settings 共享应用 store。
- Today、任务详情、分析、设置、番茄钟、开始计时、时间线菜单、编辑器丢弃确认和辅助功能信息层级进行了全局调整。
- API key 移入 device-only Keychain；AI 配置改为 Test→Save 草稿，自动建议默认关闭并需另行同意。
- Inbox/checklist AI 投影共用 UTF-8 字段、48 候选/16 KiB JSON、24 KiB prompt 和 32 KiB request body 上限；Inbox 优先固定与高频/近期任务，完整本机 symbol picker 与 78 项 AI 语义集分离，结果 UUID/icon 必须属于实际已发送集。
- Demo 默认关闭并使用独立 store；生产 store 永不物理 purge tombstone。
- Task hierarchy 改为 `parentID` 权威、canonical path 和启动/恢复 repair，消除深层路径写放大与异常图风险。
- 完成任务现在保留在任务树和历史中，但与后代一起阻止新增工作；归档分支继续隐藏。重新打开会一次恢复路径上的完成阻塞项，主应用与系统入口共用同一 trackable 判定。
- Forecast 优先使用当前任务明确的预计时长，没有预计时长时才回退到 checklist 完成证据和真实计时；父子预测分别归属，90 日 pace 不生成剩余工时。
- SwiftData 当前 schema 为 V10（`1.9.0`）：V8→V9 lightweight migration 移除可从 ledger 重建的持久 `DailySummary` cache，V9→V10 custom migration 为 Inbox item/suggestion 初始化不透明 context/revision identity 并保留旧 dismissal 语义。
- legacy Countdown 本机迁移限制 256 KiB JSON、256 条源记录、4 KiB UTF-8 标题与有限的 `[1900-01-01, 2201-01-01)` 日期；保留合法 UUID，重复 UUID 只取第一条合法记录，实际导入在 SwiftData save 成功后才设置完成 flag 并删除旧 payload。
- Pomodoro 由持久 phase 状态派生 deadline；segment edit/delete、timer stop 和 task-tree delete 保持 run/session/segment 一致。
- App Intent 提交后刷新 Widget/Watch/Live Activity，但投影失败不改变 durable mutation 结果。
- Deep link 在执行和启动排队前使用同一严格 parser；待处理队列按语义去重并限制 16 项。Watch 进程级 callback 通过弱引用 router 选择最近活跃 scene，避免旧 `ContentView`/store 泄漏或误路由。
- Watch 使用持久命令队列、typed terminal result、durable ack、20 秒 timeout、同 ID retry/discard；手机在 mutation 前拒绝超过 30 秒的旧命令，避免离线命令迟到后意外改写当前计时。
- Watch command/result/snapshot codec 与 iPhone/Watch 恢复队列增加统一结构、字节、数量、时间、唯一 ID 和 encoded-size 上限；unsafe restore 清除，pending overflow 转成明确 `queueOverflow` failure，持久队列不再可无限增长。
- Widget/Watch producer 用 Unicode-safe prefix、summary/start clamp、count cap 和 128 KiB 文本预算生成有界投影。Widget App Group 快照又在 save/load 两侧 fail closed：JSON 256 KiB、64 active/64 recent、UTF-8/时间/统计/唯一 ID 受限，损坏数据不再被误解为空账本。
- SyncConflict state 使用跨进程 file lock；Cloud export 使用 epoch/generation/fingerprint checkpoint，抵抗 lost update 与乱序回调。
- Ledger、Checklist、Rollup 实现 scoped/incremental refresh；完整历史累计保持精确，forecast pace 只统计最近 90 个本地日；50,000 segment 预算保护单记录 mutation。
- Watch store 已拆成 base、Commands、Connectivity 和 SessionDelegate 四个文件，分别拥有 observable state/restore、command queue/timeout/persistence、WCSession transport/payload/freshness 与 delegate callbacks；ledger flat-array index 与 rollup scoped mutation 也已从各自主 owner 拆出，并由 source-layout contract 约束不回退。
- Analytics overview/task snapshot 按 period 与 active-only minute bucket 缓存，重计算移出 SwiftUI `body`。
- 工程保持 Automatic Signing 和团队 `LT98S43NKA`，没有使用禁用签名绕过能力问题。

## 4. UI/UX 全局重构

### 导航与信息架构

- iPhone 删除自绘六目的地 chrome，使用 Today、Inbox、Tasks、Focus、Analytics 五个系统 `Tab`；Settings 从 Today 工具栏进入。
- iPad 在所有窗口宽度都保持同一个 `NavigationSplitView`；分屏、Stage Manager 和旋转只触发系统列折叠/显示，不切换成 iPhone 五标签根导航。macOS 继续使用 `NavigationSplitView`。
- macOS 主场景由 `WindowGroup` 改为单实例 `Window`。主窗口与标准 Settings scene 共享一个 `TimeTrackerStore`，避免多个窗口重复安装 CloudKit observers、自动 AI 和系统表面同步。
- Task Detail 是统一的只读/执行/证据页面，完整编辑通过明确铅笔 sheet 进入。

### Today、任务与时间线

- Today 改为按优先级排列的原生列表：Active Timers、今日摘要、Quick Start、可解释预测、时间线、倒计时。
- “开始计时”在所有平台都打开可搜索任务选择器，显示标题、父级路径和运行状态；任务身份先占满横向空间，Start/Switch 与 Running/Stop 位于独立命令行，不再和长标题互相挤压，也没有历史选择导致的静默启动/无反馈。
- 时间线条目主体进入任务详情，尾部独立 44 pt 省略号菜单承载编辑、补录相似记录和删除；上下文菜单保留作为次级入口。
- Today、Quick Start、Pomodoro、新记录与 Inbox 建议统一使用任务可计时判定，归档分支不再从某个入口漏出；活动任务树的归档动作要求先停止计时，历史时间片仍保留原任务归属。
- 任务/分类/Quick Start/Inbox 建议/手工时间/segment 等有草稿的编辑器在关闭前检查未保存更改。
- 任务颜色通过 light/dark 动态对比适配；关键 rows、chart、selection、Widget、Live Activity 与 Watch 补充可访问性语义。
- 移除没有证据支持的 `CADisableMinimumFrameDurationOnPhone` Info.plist 覆盖；iPhone 刷新率交给系统，流畅度以 Release runtime 和真实设备 trace 判断。

### Pomodoro

- 计划与任务是两个可见菜单，不再依赖点击标题/计时器的隐藏手势。
- Setup 已拆为组合容器、空状态、focus 参数控件、Plan/Task 选择与 timer face，不再由一个视图同时承担全部交互和展示。
- 活动界面拆分为可编译、可滚动的原生 SwiftUI 结构；状态、剩余时间、轮次、开始下一轮与停止动作明确。
- Focus deadline 在后台/启动时对账；break 不自动创建下一轮，避免用户未同意时后台生成计时事实。

### Analytics 与 Settings

- Analytics 首页先显示当前范围摘要；“复盘”按 Decisions、Quality 排列，“深入查看”按 Time、Tasks、Pomodoro、Metrics 排列。六个 typed destination 继续进入独立原生列表详情，原 Overview 用户文案已改为 Metrics。
- Landing page 与 category detail 已分成独立所有者；`AnalyticsCategory` 使用 typed navigation value/destination，避免在 root 中内联所有六类详情 composition。
- 重计算由 request key 驱动的 `.task(id:)` 执行；只有与活动 segment 相交的当前范围按分钟更新。
- 小时图提供 hour/gross/wall/primary task 的 VoiceOver 表达；辅助功能字号下范围控件改用菜单。
- Settings 分为通用、专注、数据与同步、AI 助手、高级；compact iOS 使用 sheet 适配，不强行显示窄 popover。
- 共享 Settings rows 拆为 foundation/value、action/destructive、input、presentation 与 sync-feedback 五个所有者；辅助功能字号重排、VoiceOver title/value/state 与破坏性行的显式红色文字/图标在共享层统一。
- AI editor 使用 draft → Test → model selection → Save；取消有改动草稿会确认。自动建议是另一个明确开关。

## 5. 代码正确性、同步与性能重构

### 时间账本与 Pomodoro 一致性

- Today gross/wall/average focus 使用本地日区间裁剪，跨午夜记录不再整段落入错误日期。
- `TrackedTimePolicy` 统一裁剪所有已记录时长到 reference `now`；本地新增/编辑拒绝未来时间，CloudKit/导入/历史时钟偏差记录保留但不提前计入。
- Manual/segment editor 的 DatePicker、时长与保存验证共用该 policy；`TrackedTimeDisplaySnapshot` 统一 Today timeline、Task Detail recent records 和共享 duration label，已结束 label 不再无意义每秒刷新。
- `PomodoroRun.phaseDeadline` 由持久 phase start 和计划时长派生；过期 focus 在 deadline 截断 segment/session，不把应用挂起时间算作专注。
- 编辑活动 Pomodoro segment 会重绑 task/start；关闭会完成或取消；删除会 tombstone run/session；删除任务树会停止该树所有 timers、结束 active/break Pomodoro，并保留历史。
- 所有多实体用户动作继续由 `ModelContext.performAtomicMutation` 统一提交或 rollback。

### 任务树与删除语义

- `parentID` 是任务层级权威，`TaskNode.path` 固定为 `/<UUID>`；显示路径由标题即时构建，最多显示最近六级。
- `TaskHierarchyMetadataService` 迭代修复 orphan/cycle、depth 与 canonical path；启动、任务刷新、sync restore 均执行 normalization。
- 任务移动不再因祖先链 path 改变而重写整个深子树。
- 生产 Local/iCloud/fallback/emergency store 永不物理 purge tombstone。只有隔离 Demo/UI Test store 可以清理过期 tombstone graph；可见 orphan 不因 staged import 暂缺父记录而删除。

### 同步、跨进程与系统表面

- Cloud/remote 通知经过 350 ms 合并；启动和前台刷新保留，无常驻 5 秒轮询。
- legacy `UserDefaults` 偏好迁移以 logical-key LWW winner 判断已迁移 key；winning tombstone 不再被过滤掉，旧本机值不能复活已删除偏好。
- `SyncConflictState.json` 的 read-modify-write 在递归进程锁与 POSIX `lockf` file lock 内完成，防止主应用与 Shortcuts lost update。
- 本地同步文件读写限制为权威 state 128 MiB、recovery mirror 64 MiB；读取经 metadata 与 `FileHandle limit + 1` 双重检查，写入在任何路径解析/建目录/原子替换前同时预检 state 与所需 mirror。任一写 payload 超限都保留旧的有效文件。
- local generation、sync epoch 和 export event checkpoint 绑定 fingerprint；failed/stale/out-of-order finish 不会回退 base 或清除较新的 forced-upload winner。checkpoint 限 16 个/24 小时。
- 修复旧 state 清理被排除偏好后的延迟回调竞态：清理会重算 fingerprint 并作废清理前 payload 的在途 checkpoints，旧 export completion 不能再把未过滤 base 写回。
- 修复损坏 pending forced-upload mirror 阻塞主库的问题：mirror 会单独隔离并被忽略；只有损坏权威 state 进入显式恢复流程。
- Snapshot restore 在原子 mutation 前对记录数、重复 UUID、字段/总文本 UTF-8 预算、日期、sort order、enum、Pomodoro 计划、偏好 JSON 和可证明的 session/task 矛盾做纯预检；非法 payload 整体拒绝，不静默去重/钳制，也不改写现有记录或 tombstone。缺失关联可兼容 staged CloudKit import。该边界仅覆盖显式 snapshot restore，不代表 SwiftData/CloudKit 直接 materialize 的初始 import 经过同一预检。
- App Intents 共用应用容器与领域命令。提交后用窄 lifecycle 刷新 Widget/Watch/Live Activity 和恢复 snapshot；projection 失败不会把已持久化的非幂等动作返回为失败。
- Deep-link parser 拒绝超长、credential、port、fragment、重复/未知 query 和非法 UUID；启动前 pending queue 有界、去重并在 scene teardown 清空。Watch command route 不再由 singleton closure 强持有某个 `ContentView` store。
- Watch queue 持久化；command/result 都有 durable 通道；typed terminal status、20 秒 timeout、30 秒 command-age guard、同 ID/新时间 retry、discard 和旧 snapshot-reflection compatibility 已实现。过期命令返回 invalid 且不写 receipt/ledger。
- Watch snapshot/result/command payload 验证有限日期、UTF-8 长度、summary/active-age 边界和唯一 ID；state snapshot 限 64 active/256 recent，iPhone incoming 与 Watch pending/failed 队列限 64 项，encoded queue 限 512 KiB，非法恢复 fail closed。
- Widget snapshot producer 限制数量、安全裁剪 Unicode 投影文本、summary 与 timer start，并保持 encoded JSON `<= 256 KiB`；Watch producer 保持 64 active/256 recent 与 128 KiB 总文本预算。Widget store 在 encode 前后验证字段、时间、summary、数量与唯一 ID，保存超限明确失败，读取超限/非法返回 corrupted。

### 增量计算与缓存

- Ledger 初次加载建立 segment ID/day/active/array/session indexes；范围 mutation 只 fetch/replace 相交记录及相关 session，并输出 coalesced delta。
- Ledger/Rollup index 额外跟踪 active + future-ended time-sensitive rows；时钟正常前进时局部更新，clock rewind 时全量重评，保持与 full rebuild 一致。
- 今日平均专注时长按当天范围索引查询，Pomodoro session 累计按 session index 查询，不再为两个 read model 扫描全部历史 segment。
- Checklist task-scoped refresh 只替换相关 items/visuals，避免每次 toggle 重建全库分组。
- Rollup 使用 segment before/after、scoped checklist 和 task/ancestor IDs 增量更新；完整历史 worked seconds 精确。
- Forecast pace 只保留包含今天的最近 90 个本地 Calendar 日，并只对有记录的活跃日求平均；它只将已有 remaining seconds 换算为预计活跃日。
- Analytics overview/task caches 按 range、真实 period start、task ID 与可选 active minute bucket 建 key；ledger mutation 清除 snapshots 并按相交区间失效 day bucket。
- 任务树读取路径由 mutation-owned read index 与容量四的 revision-aware projection cache 提供；旧的 624 行聚合服务按 model、index、cache、repair、遍历与组装职责拆为 7 个 50–121 行文件，并由每文件不超过 160 行的结构合同防止回退。
- Task checklist progress 和 frequent recent ranking 使用已维护索引；50,000 segment 性能测试比较单记录增量结果与全量重建，并保护 cached ranking。

### Demo、安全与隐私

- Debug/Release 自动 demo mode 均为 `off`；明确开启后使用无 CloudKit 的 `TimeTracker-Demo.store`，UI test 使用内存 store。
- API key 使用 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` 且 `kSecAttrSynchronizable=false`；旧明文迁移后删除。
