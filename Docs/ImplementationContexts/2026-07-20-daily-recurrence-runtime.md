要解决的问题：让重复任务在固定规则时区内每天只生成一个可工作的当天实例，同时保证 iCloud 分阶段同步、暂停、归档和多入口计时不会制造重复，也不会把模板误当成真实工作。

# 重复任务运行时实现上下文

## 产品语义

- 重复任务本身是模板和容器，不接受计时、番茄钟或手工时间段。
- 每天的实例是模板的直接子任务；只有实例可以接受工作记录。
- 每条规则在创建时冻结时区。日界线、开始日期和当天键都使用该时区，不随设备后来切换时区而改写历史。
- 当前运行时只补齐“今天”，不回填过去。暂停期间错过的日期永久跳过，恢复后也只生成恢复当天。
- 模板可以继续作为普通任务、清单和重复实例的父级，所以“可作为父任务”和“可直接计时”是两种独立资格。
- 任务量目标由模板快照复制到当天实例；模板上的具体完成记录不复制，避免把昨天的进度带到今天。

## 持久化与同步边界

- 规则、当天实例、任务量目标和 occurrence claim 使用确定性标识。
- 创建规则和当天实例均在共享 store lock 内执行，并在失败时回滚整张新建子图。
- 已存在的物理 claim、墓碑或 iCloud 分阶段导入留下的局部行都会阻止后台“修复式”重建，避免复活用户删除的数据。
- 重放只补齐系统拥有的缺失结构，不覆盖用户已经修改的实例标题、颜色、图标或父子关系。
- 非 canonical 规则 ID 会被拒绝，避免同一模板形成两套重复日历。

## 生命周期触发

- App 启动、场景回到前台、任务读模型变化、系统时钟变化和规则时区的下一次午夜都会尝试物化当天实例。
- 归档模板或祖先会停止生成；在仍处于前台时解除归档会重新启动调度，但只生成当前日。
- 时钟变化会先立即物化，再重排下一次边界，避免设备跨日或手动改时钟后漏掉当天实例。

## 入口一致性

- Timer、Pomodoro、手工时间段、番茄钟休息恢复和 App Intent 统一使用 direct-work 资格。
- Timer/Pomodoro 任务选择器只允许选择可直接工作的任务，但会保留不可选择的模板祖先，以便展示其可工作的当天子任务。
- Inbox、父任务编辑、任务菜单、清单视觉建议和 Today Heatmap 使用 parent/content 资格，不会因模板不可计时而隐藏组织能力。
- 创建规则前若模板仍有活动计时或番茄钟，会拒绝转换，避免工作记录悬挂在蓝图任务上。

## 代理审查记录

- `recurrence_safety_test_audit` 找到非 canonical 规则、归档后调度不重启、时钟变化漏触发、occurrence 先于 rule 同步以及模板仍有活动工作的风险；以上均已加入生产防线和回归测试。
- `direct_work_boundary_audit` 找到父任务选择器、任务菜单、详情说明、App Intent 路径和 picker 祖先容器被 direct-work 语义误伤的问题；实现已拆分 direct-work 与 parent/content 两套资格。
- `unified_workspace_release_audit` 给出源码行数预算、文件地图和文档接入要求；新文件已加入结构契约，现有历史预算问题不在本 checkpoint 内掩盖。
- `recurrence_rule_safety_tests` 独立补充未来开始日、暂停重放、时钟偏移、非 canonical 身份、活动工作、归档间隔和 iCloud 部分图等安全测试。

## 本 checkpoint 的功能边界

此 checkpoint 交付运行时、持久化、生命周期和入口安全边界；尚未交付面向用户的重复规则创建界面与任务量记录界面。因此 `Docs/userfeedback.md` 中“用户可以创建重复任务和任务量任务”必须保持未勾选，直到用户能在正式 UI 中完整创建、查看和记录，并完成实机验证。
