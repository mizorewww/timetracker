# TimeTracker 用户操作手册

状态：当前实现说明

本文只描述当前工作树中的用户行为。未来计划见 [下一步计划](NextDevelopmentPlan.md)，测试与真机门禁见 [测试](Testing.md)，精确的数据流与安全边界见 [隐私与安全](PrivacyAndSecurity.md)。

## 1. 支持范围

| 能力 | 当前状态 | 使用边界 |
| --- | --- | --- |
| iPhone、iPad、Mac 主应用 | 已实现 | 共用同一时间账本与领域命令 |
| App Intents / 快捷指令 | 已实现 | 添加收件箱项目、开始/停止计时、查询运行中计时、停止全部计时 |
| Live Activity | 代码侧已实现 | 权限、Dynamic Island、低电量和并发活动仍需真机验收 |
| Apple Watch | 代码侧已实现 | iPhone 包内嵌 companion app；有持久命令队列和明确确认，仍需真机往返、离线与功耗验收 |
| Widget | 代码侧已实现 | 只声明小型与中型系统 Widget；App Group 已配置，仍需真机共享容器和 timeline 验收 |
| JSON 导出 | 已实现 | 包含业务数据；没有 importer，不能作为可恢复备份 |

工程声明的最低版本为 iOS/iPadOS 26.2、macOS 15.7、watchOS 26.2；能否安装还取决于 Xcode、系统、设备和签名 profile。

## 2. 第一次启动

1. 启动后打开“设置 → 数据与同步”，确认存储模式与 iCloud 状态（iPhone 从“今日”右上角，iPad 从侧边栏，Mac 用系统“设置…”）。
2. 创建一个任务，或从“今日 → 开始计时”的空状态创建任务。
3. 从任务选择器中选择任务，完成第一次记录。
4. 如需 AI 建议，进入“设置 → AI 助手”，先测试连接、选择模型并保存，再单独开启“自动建议”。

TimeTracker 是本地优先应用：启用 iCloud 时业务数据由 SwiftData/CloudKit 同步，网络不可用不妨碍本地工作。若启动页显示临时内存模式或恢复模式，不要继续录入重要数据。自动演示数据默认关闭，只有明确选择或使用构建参数才创建，且使用独立、不接入 CloudKit 的 demo store。

## 3. 导航

- **iPhone**：底部五个系统标签（今日、收件箱、任务、专注、分析）。设置从“今日”工具栏以 sheet 打开，不占第六个标签；关闭后仍停留在原标签与页面。
- **iPad**：所有窗口宽度都保持同一个系统侧边栏与详情栏；变窄、分屏、旋转或 Stage Manager 只折叠或显示列，不切换成五标签。侧边栏折叠时用系统“显示侧边栏”恢复，当前目的地和任务详情保留。
- **Mac**：单实例主 `Window` + `NavigationSplitView`；系统 Settings 是独立场景但与主窗口共享应用级 store。“设置 → 快捷键”按创建、计时、整理、导航和数据分组提供 16 个主要操作，可录制/清空/恢复默认，改动立即反映到菜单。

现有 Mac 快捷键：`Command-1…5`（五个主目的地，可配置）、`Shift-Command-M`（手动补录）、`Shift-Command-S`（开始所选任务）、`Shift-Command-P`（为所选任务开始番茄钟）、`Command-R`（刷新数据）均可配置；选择任务开始、停止所选任务、添加子任务、归档所选任务、新建/排序分类、生成 AI 任务计划默认未分配但仍可录制；`Command-N`（新建任务）与 `Command-,`（设置）是 macOS 标准命令、不可改写。依赖当前任务或页面状态的菜单项会在不适用时置灰。快捷键只在 Time Tracker 为前台应用时生效，且只保存在这台 Mac，不通过 iCloud 同步。

## 4. 今日与计时

“今日”先回答“现在正在做什么”，再提供当天概览与下一步动作。iPhone 依次显示：正在计时、今日摘要、本周时间、活动热力图、快速开始、今日时间线、预测、倒计时；iPad/Mac 保持相同优先级并在宽屏组成两列。

1. 没有活动计时时“开始计时”是主操作，点击后打开可搜索的任务选择器；已有活动计时时按并行设置显示“再开始一个计时”或“切换计时”。三种状态由同一入口驱动，只改变准确的标题与图标。
2. 运行中的任务集中在“正在计时”区，点按摘要不会停止计时；每行保留右侧独立的红色停止按钮，不再重复“运行中”标记。未运行任务的开始/切换与运行任务的停止使用同样大小与位置的圆形按钮，并读出目标任务和动作；任务文字不是隐藏的整行停止热区。停止后选择器保持打开，任务回到可选列表；切换会先停止冲突计时再开始所选任务。
3. 普通计时停止后，如果在不足 60 秒内从 App、快捷指令、Watch 或 Widget 重新开始同一任务，且空档没有记录其它工作，应用把它当成一次误停：时间线只保留一个连续时间片，空档也计入该任务。恰好 60 秒、期间切换过其它任务、手动补录、日历记录和番茄钟都保持独立；旧界面或系统表面保存的上一条时间片停止指令会安全失效。
4. 没有匹配任务时可在选择器内创建任务；Today 不再放置与当前计时并列的通用“新建任务”按钮。
5. “快速开始”合并固定任务与最近高频/近期任务。每项先显示任务图标与标题，子任务另用次级路径文字区分，根任务不重复路径。点击任务标题/卡片打开详情；右侧独立的“开始/切换/停止”按钮才改变计时。有未保存更改时关闭编辑器会要求确认丢弃。
6. 点击活动计时、预测或时间线主体打开任务详情；时间线尾部的省略号菜单提供编辑、补录相似记录和删除。

指标含义：总时长（Gross）为所有时间片相加、并行部分重复累计；墙钟时间（Wall）为区间并集、并行只计一次；重叠时间为二者之差。“本周时间”按天用并列柱比较两个口径：左侧绿色为 Gross、右侧蓝色为 Wall，底部图例、固定位置与 VoiceOver 同时说明。跨午夜的时间片按所选本地日边界裁剪。

手动补录与时间片编辑要求结束晚于开始且不延伸到未来；开始/结束 DatePicker 上限为当前时刻，无效范围显示错误并禁用保存。若 iCloud、历史导入或旧设备时钟偏差已产生未来结束时间，App 保留该记录，但 Today 时间线、任务近期记录和共享时长标签都只显示到当前时刻；未来才开始的部分在真正到达前计为零。

## 5. 收件箱

1. 输入标题提交；提交只有在持久化真正成功后才清空输入框（只读恢复、保存失败或尚未完成存储配置时保留草稿并显示错误）。
2. 可完成、编辑或删除条目；待整理条目直接长按拖动排序，无需先进入“排序”模式，输入行与已完成区不参与移动。
3. 明确开启“自动建议”后，新条目自动请求归属建议；失败时显示具体错误并可在建议条中重试。当前没有独立的手动请求入口或建议编辑器。
4. 推荐卡片分三行：第一行完成圆圈 + Inbox 原文 + 更多菜单；第二行“推荐：”预览模型生成的图标、颜色与目标任务；第三行把放弃与接受固定在左右两端（紧凑宽度显示 ×/✓，宽界面显示“放弃/添加到任务”）。接受后才把这套外观连同标题转换为目标任务下的 checklist；目标任务后来归档、被历史 tombstone 隐藏或不可用时“接受”禁用但仍可放弃。
5. 放弃建议后应用在 iCloud 合并或条目内部重建后继续记住“当前标题版本已放弃”；真正修改标题视为新版本，允许再次自动建议。同名但分别创建的两个条目不共享放弃状态。

每次 Inbox 建议发送全部可工作的任务和全部可见分类，Checklist 建议发送完整标题与所属任务路径，三种 AI 功能都发送与本机图标选择器一致的完整 SF Symbols 目录，不用固定候选数或请求字节预算静默删除上下文；请求构造不会改写你保存的原文。发送字段与安全边界见 [隐私与安全](PrivacyAndSecurity.md)。

## 6. 任务、分类与清单

- 分类组织根任务，父子关系组织任务分支；展开状态只影响界面，不改变持久层级。
- 任务列表、侧边栏和选择器使用同一套任务摘要：标题最优先、正常字号最多两行；树中的行不重复父级路径，平铺结果在标题下显示父级路径。随后一行把 checklist 进度放左侧，被动的绿色计时图标、已工作时长和进入详情的箭头放右侧。绿色图标只说明正在计时，不是停止按钮；选择器另用统一的右侧圆形按钮执行开始/切换/停止，详情显示明确停止动作。
- 在任务页点按“+”选择“生成任务计划…”可让 AI 基于完整的当前 Category/Task/Checklist 工作区规划变更。先核对发送提示中的三类实体数量，再点“生成”；生成期间可停止请求，已输入需求保留。
- 模型不会直接写入数据：它只能在本机内存草稿中用结构化工具读取/复用/新建/更新/删除 Category，创建/更新/建议归档 Task，创建/更新/删除 Checklist。已有实体用稳定 ID 区分（同名 Task 仍按完整路径识别）；已有 Category 只在唯一匹配时复用，多个同名项要求重新处理而不猜测。
- 生成结果先以只读原生列表显示 create/update/archive/delete/reuse 数量、完整所属路径和修改前→修改后。核对后点“应用 N 项更改”；包含删除或归档时另有系统破坏性确认。提交会一次性应用整份建议，任一校验失败时全部回滚。若生成后另一窗口/设备/同步改动了工作区，旧预览不覆盖新事实，应用提示并零写入。
- 点击任务行进入只读优先详情：系统导航栏与首张身份卡都显示任务标题，身份卡下一行显示父级路径（根任务显示“根”），卡片不重复“运行中”。运行时计时状态只由紧接的明确“停止”动作表达，“添加时间”仍保留。随后是清单、预测、备注，以及异步载入的摘要、分析与近期记录；分析计算时只在分析区显示加载行，不以整页转圈阻塞操作。
- 详情用系统返回按钮；返回列表后搜索词与树展开状态保留。iPad/Mac 侧边栏中打开任务会保持选中，点另一项一次替换选中态与详情，不先退回列表；草稿未保存时取消丢弃停留在原任务，确认后才切换。任务被归档或同步带来旧客户端 tombstone/表明不存在时才自动关闭详情。
- 点击铅笔进入完整编辑表单；取消有改动的任务、分类、手工时间或时间片编辑器会要求确认。iPhone/iPad 的“符号与颜色”进入同一编辑流程的下一页，返回不等于保存；Mac 上该选择器为 popover，Blossom 从点按的色块中心展开。
- 任务移动会阻止把任务移入自身、后代或不可接收工作的父节点。分阶段同步暂时缺少父节点或检测到循环时，界面先把安全断点显示为根节点，等待后续同步；显式恢复快照时才规范化异常层级。
- Checklist 是任务内部步骤，不能独立计时；行可直接长按拖动排序，未完成项与已完成项分别排序、不能跨组。删除无常驻垃圾桶/“更多”按钮：iPhone/iPad 向右滑露出“删除”（不会整行滑到底直接执行），长按可从上下文菜单删除，Mac 用右键/Control-click。分类排序与 Quick Start 固定项同样直接拖动。
- 预计时长可设 15 分钟步进、最多 10 小时；明确预计时长直接形成当前任务自身预测，未设置时才回退到 checklist 完成证据与真实计时。父任务仍另行汇总子任务预测。完成全部 checklist 只表示内部步骤完成，不改变可工作性、不停止计时、不阻止继续工作。
- 只有任务自身或祖先已归档、被历史 tombstone 隐藏或不存在时才不能接收新工作或成为新父任务。任务编辑器保存时核对打开草稿时的任务、checklist 外观与分类版本；旧草稿被拒绝时可“重新载入最新版本”（确认后丢弃当前草稿）或“保留我的草稿”。
- 开始计时、快速开始、番茄任务和新建记录的选择器统一排除不可接收新工作的任务；历史时间片编辑仍保留原始任务归属。普通任务只有 Archive/Restore：菜单与滑动复用“归档”，设置中的“已归档任务”负责恢复（先恢复父任务再后代）。应用仍理解旧设备/iCloud 的删除 tombstone 以防旧数据复活，但界面不提供普通任务“删除”。

同名任务可能属于不同路径；开始计时或接受 AI 建议前应同时核对标题与显示路径。

## 7. 番茄钟

1. 用“计划”菜单选择方案，主操作下方同时列出专注、短休息、长休息和轮数。
2. 点“任务”打开可搜索任务表，按标题或完整路径查找并确认绑定任务（只属于当前页面，不会自动启动专注或改写全局当前任务）。
3. 点击“开始专注”会创建 `PomodoroRun`、`TimeSession` 与 `TimeSegment`。
4. 专注 deadline 由持久阶段状态与计划时长计算；后台挂起或重启后按同一 deadline 对账并把账本截到计划结束时刻，不把挂起时间算作专注。
5. 专注结束后进入短休息或长休息。休息中可“跳过休息”，倒计时归零后“开始下一轮专注”；两者都需要明确点按，后台不会擅自创建下一段专注。
6. 最后一轮结束后流程完成并结束关联 session；“停止番茄钟”需要确认，非常短且主动取消的首次尝试可能连同记录一起丢弃。
7. 绑定任务在休息期间归档、被 tombstone 隐藏或因祖先变化不可工作时，下一轮按钮停用但可安全停止当前流程；Checklist 完成不触发这项阻止。继续/完成/停止固化打开操作时的阶段版本，旧按钮/确认框不会误操作新阶段。
8. VoiceOver 把阶段、完整任务路径与本地化剩余时长作为一个计时器语义朗读；视觉进度条不重复播报。编辑/删除活动番茄时间片会同步重绑或 tombstone 对应 run。

## 8. 分析

分析首页先显示当前范围摘要，把可行动的“决策/质量”放“复盘”区，“深入查看”再提供时间规律、任务与分类、专注轮次、总计与定义；每行直接显示它回答的问题、当前答案与将打开的详情名称。任务与分类详情先显示分类分布，再显示任务和根任务分布；分类分布项目是只读统计。活动热力图在首页只显示一个入口，打开独立页面并沿用设置中的范围与所选任务，不重复分析的日期筛选。

- 范围以日、周、月选择；历史日期可用“回到今天”返回当前周期，并可按参考日期前后移动。连续前后移动“月”范围时保留开始导航时的本地日号与时分秒，目标月没有该日时暂用月末并在较长月份恢复（如 1 月 31 日 → 2 月 28/29 日 → 3 月 31 日）。
- 当前范围存在相交活动计时时在下一个真实分钟边界刷新；历史范围与无相交活动计时的范围不每 30 秒重算，当前静态范围只等待下一个本地日历日，历史范围不保留时钟任务。回到前台、系统时钟或时区变化时重新核对。
- 同一周期刷新时保留已显示内容并显示轻量进度指示；切换到不同周期只显示新周期的加载状态，绝不把旧周期指标冠以新范围。
- 已结束的历史周期统计到精确结束边界，不漏午夜前最后一秒；跨所选历史周期仍在运行的记录只计周期内部分；未来周期在真正开始前为空。
- 当前周期的增减只与上一周期的相同日历进度比较（如周四 14:30 对上周四 14:30），跨夏令时按本地钟点对齐，长月超出上一短月的日期对齐至月末；已完成历史周期与上一个完整周期比较。没有目标值时增加和减少都只用中性样式。
- 周/月趋势只显示已开始的本地日，不在当前月末尾补未来零值；不足一分钟的数据按小数分钟参与绘图。三个口径（Gross = 各计时相加、Wall = 合并重叠只算一次、Overlap Excess = 二者之差）在“总计与定义”中说明。
- 预测优先使用明确预计时长，未填写时才由 checklist 完成证据与真实计时驱动；最近 90 个本地日只用于估算“以近期活跃日节奏还需多少天”，不凭空制造剩余小时。

## 9. 系统入口

### 快捷指令与 Siri

系统可发现“添加收件箱项目”“开始计时”“停止计时”“获取运行中的计时”“停止所有计时”。在“快捷指令”中新建并添加对应操作；“添加收件箱项目”必填标题，“开始计时”需选一个当前可计时的任务（遵守并行设置，已在计时时不重复创建），“停止计时”需选一条运行中的计时并固化其时间片 ID，目标失效时不回退停止其它。这些动作在应用未打开时也使用同一原子领域命令：只要持久提交完成即可返回，同步保护、Widget、Watch 与 Live Activity 会在后台追赶，短暂旧投影不表示动作失败，不要仅因未刷新就重复执行。若快捷指令未出现，先启动一次主应用再重新搜索（系统可能缓存旧元数据）。设计细节见 [快捷指令设计](Shortcuts/README.md)。

### Live Activity

iPhone 允许时，开始第一条计时后应用会在账本刷新时自动请求并维护 Live Activity，最后一条活动计时停止后自动结束；它只是账本投影。并行计时只维护一个：最早开始且仍在运行的计时是主项，锁屏按“任务图标 / 标题与路径 / 已运行时间”显示，展开的灵动岛只保留“图标 / 标题 / 时间”一行，空间不足或辅助字号用同一组件自适应。它不堆叠附加计时数量或停止控件；点按回到“今日”，停止在主应用正在计时区完成。紧凑态显示可截断的身份与时间，最小态优先显示受 stale 边界约束的时间（新鲜时更新，进入更新延迟后冻结），任务色 keyline 保留身份线索。系统可能因权限、低电量或并发限制展示或更新；若系统报告陈旧，界面会显示明确状态，主应用账本计时不受影响。

### Apple Watch

在 iPhone Watch app 启用“自动安装 App”并安装“时间追踪”，在 iPhone 打开一次主应用再打开 Watch app；保持附近并让 iPhone 完成启动与刷新。Watch 用三张系统纵向分页，表冠或上下轻扫依次切换“正在计时 / 快速开始 / 所有任务”：

- 第一次收到快照通常有活动计时就打开“正在计时”，否则“快速开始”；若有命令失败、正在发送/排队、连接错误或陈旧等需处理状态，即使没有计时也先打开“正在计时”。后续状态/失败不会把你从当前页拉走，此时“快速开始/所有任务”顶部出现 ≥44 pt 的“查看状态”按钮返回处理。
- “快速开始”最多显示四个未运行任务（先固定项，再用高频/近期补足），不改变“所有任务”排序。“所有任务”保留运行任务并按历史时间片数量、最近开始时间排序，相同项用稳定任务 ID 决定；不能接收新工作的任务不出现。
- 开始：点按尚未运行的任务行；已有计时时也可选另一任务，iPhone 在提交时读取全局“允许并行计时”决定并行或切换。行尾播放图标变沙漏表示等待确认，期间不可重复提交。查看运行项：绿色计时器图标表示正在运行，点按回到“正在计时”而不停止。
- 停止只在“正在计时”页点按对应行，发送该时间片 ID，只停这一条。
- 每个新命令先进入本机持久队列并用耐久 `transferUserInfo`，可达时再用即时消息加速。界面显示成功/重复/任务缺失/时间片缺失/无效/失败/超时；超时由 Watch 本机等待 20 秒产生。20 秒未收到结果时命令移入可重试状态，重试保留原 command ID 但刷新发送时间；成功但列表短暂旧时请等待后台快照或打开 iPhone，不要新建命令。手机拒绝超过 30 秒的旧命令并返回无效，可在确认状态后重试或丢弃。
- “正在计时”页先列命令问题，再列连接/队列/更新状态，最后列活动计时；主页只展开第一个问题，多个时进入“全部待处理操作”逐项重试/丢弃（丢弃只移除本机提示，不撤销可能已完成的操作）。
- 陈旧快照的已用时间冻结在最后确认值；手腕放下或 Always On 降亮时任务标题与路径按系统隐私遮盖。状态快照最多 64 个活动计时与 256 个可工作任务，共用 128 KiB 文本预算；手机按优先级决定进入上限的任务，并为旧版 Watch 兼容重排传输数组。新 Watch 连接旧手机时安全回退到手机发送顺序。异常长文本按完整 Unicode 边界缩短但不改写主 App。Watch 待处理/失败各最多 64 项，队列编码最多 512 KiB；超出时最旧命令转成可见失败项，损坏/重复/异常大队列在恢复时丢弃。

### Widget

当前只声明小型与中型。iPhone/iPad 长按主屏幕添加；Mac 用 Control-点按桌面 → 编辑 Widget。首次添加后先打开一次主应用把最新快照写入 App Group；系统决定刷新时机。

- 点击小组件非控件背景、正在计时摘要中除停止按钮外的区域或普通“打开”提示，只打开“今日”，不开始或停止任务。
- 小型空状态中只有带播放图标且显示任务名的链接会开始该任务；中型右侧 Quick Start 只有具体任务行会开始对应任务。
- 当前计时摘要的 app-opening 控件明确表示“打开 Time Tracker 后停止”，只停止当前显示的时间片，目标失效时不会误停其它并行计时。

Widget 能区分等待快照、共享容器不可用与快照损坏。单个快照最多 256 KiB，活动计时与近期任务各最多 64 项，共用 128 KiB 文本预算；生成时按完整 Unicode 边界缩短超长标题/路径并把统计/异常计时开始裁到安全范围（只影响投影，不改写账本）。非法日期、负统计、重复 ID 或过长文本视为损坏快照，不当作空账本。发行前仍需真机验证写入、读取、timeline reload 与离线状态。

## 10. 设置、AI、同步与数据安全

设置分通用、专注、数据与同步、AI 助手、高级；Mac 另有设备本地的快捷键分类。外观跟随系统，不提供应用级亮/暗覆盖。辅助功能大字下标题与输入框改为纵向排列，VoiceOver 读出行标题、当前值与同步状态。

**倒计时**：在“设置 → 通用 → 倒计时”管理跨设备显示的纪念日/截止日期。新增默认“新事件”、日期七天后；标题只在保存/Return/离开输入框时提交，且不能为空、不含换行/控制字符、UTF-8 后不超过 4 KiB；日期调整立即保存，删除需确认。

**AI 助手**：配置用草稿工作流——输入 endpoint/API key 只改 sheet 内草稿，不逐字持久化；“测试连接”获取模型列表但不保存凭证；选模型与“思考强度”后“保存”，取消或下拉关闭有改动的草稿会要求确认。“保存”先完整检查四项再作为一次偏好提交，任一无效/超限不留半成品；API key 属于独立本机安全存储，偏好提交失败时尽力恢复旧密钥并显示错误。保存后再明确开启“自动建议”（只本机、默认关闭）。三个“编辑…指令”入口调整 Inbox 路由、Checklist 视觉和任务规划，作为普通偏好同步、按 256 KiB 偏好边界验证、可恢复默认；它们不能覆盖固定响应/工具协议、稳定身份、全量上下文、原子提交与层级安全规则。API key 只存本机 Keychain，endpoint/模型/模型列表/思考强度是可同步普通偏好；远程 endpoint 必须 HTTPS，只有严格本机回环地址允许 HTTP。DeepSeek V4 的三种请求都显式开启 thinking 并使用当前 high/max，其它模型不会收到专属参数。选择第三方服务即授权其按政策处理请求内容与保留数据；发行前必须确认 endpoint 服务方、用途、保留期与删除方式与产品披露一致。

任务计划只在用户从任务页明确点按“生成”时发送，包含当次需求、任务规划指令、允许的图标与颜色列表，以及完整的当前 Category/Task/Checklist 文本、稳定 ID、关系、完整路径和可编辑元数据；发送前显示三类实体数量。API key 只用于 Authorization header；时间历史、Inbox、设备 ID 与本地 revision baseline 不发送。模型只能修改本机内存建议，最终仍必须经过只读 diff 审阅和明确 Apply，不能自动写入或绕过破坏性确认。精确字段与大小失败行为见 [隐私与安全](PrivacyAndSecurity.md)。

**iCloud**：日常查看都在“设置 → 数据与同步 → 同步”。状态卡区分可用、正在检查、最近的 iCloud 活动、本地模式、需要重启、失败、冲突和临时存储；“检查 iCloud 账户”只确认本设备能否访问账户并更新状态卡，不手动触发同步也不选择覆盖方向。CloudKit 导入/导出由系统自动执行，没有无法保证结果的“立即同步”按钮；改变“iCloud 同步”开关后先完全关闭并重新打开 App（容器只在下次启动切换）。状态卡只把 CloudKit 明确完成且本机刷新/冲突检查都成功的 import/export/setup 显示为最近活动，单独收到 remote-store 变更不代表云操作完成。

“同步恢复”是覆盖工具：无冲突时默认只显示“打开恢复选项”，主动展开后才出现两个方向；真实冲突时直接先显示本机与 iCloud 摘要再显示两个方向。主界面只显示可忽略的冲突提示，点“查看副本”进入设置比较两侧摘要。确认覆盖前若任一侧内容又变化，应用拒绝旧确认并要求重新核对；两个排队方向互斥，容器已进入恢复后旧设置窗口的另一方向按钮被拒绝。自动恢复（fallback 后重新启用 iCloud）只做比较：保护本机分支、建立 fresh cache、等完整 setup + 首次 import 后比较，相同则继续、不同则显示冲突，绝不在比较前静默上传覆盖云端；只有明确选择“用 iCloud 替换本设备数据”时才跳过本机补抓。下载/自动比较期间保持只读直到同一新 store 的 setup 成功并完成首次 import；恢复中断后下次启动只复用已完成 setup+import 的同一会话，缺少任一回执会重新建立 fresh cache。若找不到可证明安全的本机上传快照或无法删除旧 store/同步状态，本次启动不会连接 CloudKit，也不会把 pending 恢复标成完成——请处理存储空间/文件保护/容器错误后再重启。损坏的同步恢复状态会被隔离，主 store 能打开时建立新基线。CloudKit 可能先送计时段、稍后送任务/会话，应用保留原始行但在关系补齐前不计入今日/分析/Widget/Watch。

**JSON 导出**：打开“设置 → 数据与同步 → 数据”点“导出 JSON”，成功后才会打开系统文件导出器；取消不是错误，读取/序列化/写入失败只在当前设置场景显示。导出是版本化 `timetracker.cloudSyncedData` envelope，过滤 API key 与设备本地开关后的可同步业务数据，不会自动上传。当前没有 importer、校验和、加密和事务恢复，因此 **JSON 导出不是可验证、可恢复的备份**；失败时不会用空对象生成看似成功的文件。请只保存到可信位置。

**手动补录**：在任务列表/详情选“添加时间”，或 Today 时间线“添加相似时间”（Mac 还可按 `Shift-Command-M`）。核对归属任务、调整开始/结束时间（默认结束于当前时刻的最近 30 分钟，结束须晚于开始且不未来），可填备注后保存。提交时会再次检查任务仍可计时；若另一窗口已归档该任务或同步带来 tombstone，当前草稿不会写入旧归属。取消有改动的草稿需确认；保存后记录进入同一账本与分析，不启动活动计时。

**删除与维护**：清空业务数据的入口是“设置 → 高级 → 维护 → 重置数据”，需在确认对话框再次选择“删除所有数据”。普通 Local/iCloud/local-fallback/emergency 生产 store 永不物理清除 tombstone（没有每台离线设备的删除确认），因此生产设置不显示“永久优化/清理 tombstone”入口，该入口只用于隔离的 Demo/UI Test store。“重置数据”是破坏性逻辑删除并可能经 iCloud 传播，还会清除本机 Keychain API key 与设备本地自动建议同意，但不切换设备本地 iCloud 启动开关。

- 支持完整 Dynamic Type；辅助功能字号下密集横行改为纵向或菜单布局，关键操作使用有标签的系统 `Button`，装饰图标从辅助功能树隐藏。
- 小时图表提供可逐项读取的时间、总时长、墙钟时间和主要任务语义；iPad/macOS 侧边栏用系统提供的显示/隐藏方式。

若仍出现遮挡，请记录设备、页面、语言、横竖屏、外观和字体档位并附截图；不要通过调小系统字体规避问题。

## 12. 故障排查

- **无法开始或保存**：查看当前场景的错误提示与“设置 → 数据与同步”的存储模式；若是临时内存/待恢复模式先停止录入并重启修复。确认任务及其祖先未归档、未被 tombstone 隐藏且未丢失（Checklist 全完成不会阻止计时），且开始不在未来、结束晚于开始且不未来。若编辑器提示任务已在其它位置更改，可“重新载入最新版本”（丢弃未保存输入）或“保留我的草稿”。
- **启动进入只读恢复页**：先停止录入；点“复制诊断”可复制状态/错误/持久化模式/store 路径（可能含本机目录，发送前脱敏，不要附 API key 或任务内容）。Mac 可“打开数据文件夹”核对并使用页面“退出”完整结束；不要手动删除或替换 store。检查可用空间、文件保护、Apple ID、iCloud Drive 和网络后重开。
- **数据没有同步**：确认同一 Apple ID、iCloud Drive 允许且当前设备开关开启；重启应用让容器模式生效、保持前台一段时间并查看账户/持久化模式；不要交替点击两个覆盖方向；冲突时先判断哪一侧权威；若提示排到下次启动或进入只读恢复，完全关闭 App 后确认 iCloud 可用再重开，恢复完成前不要继续录入。
- **AI 测试或建议失败**：检查 endpoint、API key、模型、网络、额度和服务方状态。远程 HTTP、伪装 loopback、跨源 redirect 和 HTTPS 降级会被拒绝；服务端超过 60 秒或返回超过 2 MiB 也会明确失败。重新编辑凭证后必须再次“测试连接”并保存，自动建议仍需单独开启。生成任务计划失败时不写入任务库；context counts/bytes 超出供应商能力时应改用支持更大上下文的模型，应用不会静默截断或回退旧 JSON。stale workspace 或任一步失败会整份回滚并保留预览。
- **Watch 命令未确认**：打开 iPhone 主应用并保持附近，等 typed result 或新快照；typed result 已成功但快照稍旧时先等待，不要重试；只有 terminal result 超时/失败且核对真实状态后才重试。确认手机真实状态后可丢弃不需要的失败项。
- **Widget 为空或报错**：先打开主应用回到前台让后台补齐快照，再等系统刷新；仍为空时检查 App Group/profile。共享容器不可用、快照缺失和损坏是不同故障；空状态或短暂旧状态不表示主应用数据丢失。
- **番茄钟在后台结束**：重开应用，专注阶段会按持久 phase deadline 对账并截断账本；休息结束后需手动点“开始下一轮专注”。
- **Mac 出现多个状态或重复自动请求**：当前只创建一个主窗口，Settings 与主窗口共享 store；若升级后仍观察到，完全退出旧构建并重启，确认没有另一个安装路径或旧进程。
