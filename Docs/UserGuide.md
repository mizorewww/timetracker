# TimeTracker 用户操作手册

状态：当前实现说明

校对日期：2026-07-19

本文只描述当前工作树中的用户行为。未来计划见 [下一步计划](NextDevelopmentPlan.md)，测试和真机门禁见 [审核报告](Audit-2026-07-14.md)。

## 1. 支持范围

| 能力 | 当前状态 | 使用边界 |
| --- | --- | --- |
| iPhone、iPad、Mac 主应用 | 已实现 | 共用同一时间账本与领域命令 |
| App Intents / 快捷指令 | 已实现 | 添加收件箱项目、开始计时、停止计时 |
| Live Activity | 代码侧已实现 | 权限、Dynamic Island、低电量和并发活动仍需真机验收 |
| Apple Watch | 代码侧已实现 | iPhone 包内嵌 companion app；有持久命令队列和明确确认，仍需真机往返、离线与功耗验收 |
| Widget | 代码侧已实现 | 只声明小型与中型系统 Widget；App Group 已配置，仍需真机共享容器和 timeline 验收 |
| JSON 导出 | 已实现 | 没有 importer，不能作为可恢复备份 |

工程当前声明的最低版本为 iOS/iPadOS 26.2、macOS 15.7、watchOS 26.2。能否安装还取决于 Xcode、系统、设备和签名 profile。

## 2. 第一次启动

1. 启动后打开“设置 → 数据与同步”，确认当前存储模式与 iCloud 状态。iPhone 从“今日”右上角打开设置 sheet；iPad 从侧边栏进入；Mac 使用系统“设置…”场景。
2. 创建一个任务，或从“今日 → 开始计时”中的空状态创建任务。
3. 从“开始计时”任务选择器中选择任务，完成第一次记录。
4. 如需 AI 建议，进入“设置 → AI 助手”，先测试连接、选择模型并保存，再单独开启“自动建议”。

TimeTracker 是本地优先应用。启用 iCloud 时，业务数据由 SwiftData/CloudKit 同步；网络不可用不妨碍本地工作。如果启动页显示临时内存模式或恢复模式，不要继续录入重要数据：内存数据会在进程结束后消失，恢复模式也会阻止写入。

Debug 和 Release 的自动演示数据模式都默认为关闭。Debug/内部工具只有在你明确选择或使用构建参数时才创建演示数据；演示数据使用独立的 `TimeTracker-Demo.store` 且不接入 CloudKit，不会自动写入真实用户 store。

## 3. 导航

### iPhone

底部是五个系统标签：今日、收件箱、任务、专注、分析。设置从“今日”工具栏以 scene-owned sheet 打开，不占第六个标签，也不压入“今日”的导航栈；关闭后仍停留在原标签和原页面。每个标签使用自己的原生导航栈，设置 sheet 内部维护自己的分类导航。

### iPad

iPad 在所有窗口宽度都保持同一个系统侧边栏和详情栏。窗口变窄、分屏、旋转或进入 Stage Manager 时，`NavigationSplitView` 只折叠或显示列，不会切换成 iPhone 的五标签根导航；侧边栏折叠时使用系统“显示侧边栏”操作恢复，当前目的地和任务详情会保留。

### Mac

Mac 使用单实例主 `Window` 和 `NavigationSplitView`，不会为每次“新建窗口”复制一套同步观察器或自动化。系统 Settings 是独立设置场景，但与主窗口共享同一个应用级 store；标准“设置…”菜单与快捷键均可打开它。

现有 Mac 快捷键：

| 快捷键 | 操作 | 使用条件 |
| --- | --- | --- |
| `Command-1` … `Command-5` | 依次打开今日、收件箱、任务、专注、分析 | 会先关闭当前任务详情导航 |
| `Command-N` | 新建任务 | 主窗口可用 |
| `Shift-Command-M` | 手动补录 | 主窗口可用 |
| `Shift-Command-S` | 开始所选任务 | 必须已经选中任务 |
| `Shift-Command-P` | 为所选任务开始番茄钟 | 必须已经选中任务 |
| `Command-R` | 刷新当前数据 | 重新读取当前存储，不选择同步覆盖方向 |
| `Command-,` | 打开设置 | macOS 标准设置快捷键 |

## 4. 今日与计时

“今日”先回答“现在正在做什么”，再提供当天概览和下一步动作。iPhone 依次显示：正在计时、今日摘要、快速开始、今日时间线、预测、倒计时。iPad 与 Mac 保持相同优先级；详情栏扣除左右留白后仍有足够空间时，快速开始和时间线在主栏，预测和倒计时进入较窄的辅助栏，窗口变窄或辅助内容为空时自动回到单栏。内容宽度有上限，不会超出 Split View 详情栏，也不会把卡片拉满超宽屏幕。

1. 没有活动计时时，“开始计时”是页面的主操作；点击后总会打开可搜索的任务选择器，不会静默选择旧任务。
2. 已有活动计时时，若允许并行计时，操作显示为“再开始一个计时”；若不允许并行，操作显示为“切换计时”。切换会遵守共享计时规则，先结束冲突的活动计时，再开始所选任务。
3. 运行中的任务集中显示在“正在计时”区，点按任务内容不会停止计时；一行只保留旁边的红色停止按钮，不再同时重复“运行中”标记。紧凑 iPhone 使用停止图标，较宽界面显示“停止”，两者的辅助标签都会读出目标任务。停止后选择器会保持打开，刚停止的任务重新回到可选列表。未运行任务的行尾用播放或切换图标表达命令；切换会先停止冲突的活动计时，再开始所选任务。
4. 没有匹配任务时，可在任务选择器内创建任务；Today 本身不再放置与当前计时并列的通用“新建任务”按钮。
5. “快速开始”合并固定任务和最近高频任务。每项先显示任务自己的图标与标题；子任务另用次级文字显示父级路径，根任务不重复显示路径，因此同名子任务也能按所在分支区分。点击任务标题或卡片内容始终打开任务详情；右侧独立的“开始”或“切换”按钮才会按当前并行设置启动计时。任务正在运行时，经过时间和右侧独立“停止”按钮已经表达状态，不再额外显示“运行中”；停止只结束该任务当前的时间片，不会把任务内容暗中变成 toggle。编辑器使用相同的标题与父级路径规则；有未保存更改时，关闭前会要求确认丢弃。
6. 点击活动计时、预测或时间线主体可打开任务详情；时间线尾部的省略号菜单提供编辑、补录相似记录和删除。

指标含义：

- 总时长（Gross）：所有时间片相加，并行部分会重复累计。
- 墙钟时间（Wall）：至少一个任务正在运行的区间并集，并行部分只计一次。
- 重叠时间：并行计时造成的 Gross 与 Wall 差异。

跨午夜的时间片会按所选本地日边界裁剪，不会把整段都计入开始日或结束日。

手动补录和时间片编辑要求结束晚于开始，且时间不能延伸到未来。开始/结束 DatePicker 的最大值是当前时刻；无效范围会显示明确错误并禁用保存。如果 iCloud、历史导入或旧设备时钟偏差已经产生未来结束时间，App 会保留该记录，但 Today 时间线、任务近期记录和共享时长标签都只显示到当前时刻；未来才开始的部分在时间真正到达前计为零。

## 5. 收件箱

收件箱用于“先捕获、后整理”：

1. 输入标题并提交。
2. 可完成、编辑或删除条目。
3. 明确开启“自动建议”后，新条目会自动请求归属建议；请求失败时会显示具体错误并可在建议条中重试。当前版本没有独立的手动请求入口，也没有建议编辑器。
4. 建议条会预览模型生成的图标、颜色和目标任务名称；接受后才会把这套外观连同标题转换为目标任务下的 checklist，放弃建议不会修改任务。如果目标任务后来归档、删除或不可用，“接受”会禁用，但仍可放弃建议，不会留下无法处理的条目。
5. 放弃建议后，应用会在 iCloud 合并或条目内部重建后继续记住“当前标题版本已放弃”；真正修改标题会视为新版本并允许自动建议再次处理。同名但分别创建的两个条目不会共享放弃状态。

提交只有在持久化真正成功后才会清空输入框。如果 iCloud 恢复模式暂时只读、数据库保存失败或应用尚未完成存储配置，原草稿会留在输入框中，并显示对应错误；排除问题后可直接重试，无需重新输入。

只有在“AI 助手”中明确开启自动建议后，新条目才会自动发起请求。每次 Inbox 建议最多发送 48 个可工作任务，优先包含 Quick Start 固定任务和高频/近期任务；当标题或路径异常长时，只会在网络请求副本中按完整 Unicode 字符缩短，不改写你保存的原文。发送字段与精确上限见 [隐私与安全](PrivacyAndSecurity.md)。

## 6. 任务、分类与清单

- 分类组织根任务；父子关系组织任务分支。展开状态只影响界面，不改变持久层级。
- 任务列表、侧边栏和任务选择器使用同一套任务摘要。标题最优先，正常字号最多显示两行；位于树中的行不重复父级路径，搜索或其它平铺结果会在标题下显示父级路径。随后一行把 checklist 进度放在左侧，把被动的绿色计时图标、已工作时长和进入详情的箭头放在右侧。绿色计时图标只说明正在计时，不是停止按钮；要停止必须进入明确显示“停止”的计时区域或任务详情。
- 在任务页点按右上角“+”，选择“生成任务计划…”可从一段自然语言需求生成分类、任务层级和 checklist 草稿。输入期望结果、习惯或项目后点“生成”；生成期间可以停止请求。
- 生成结果先以原生列表预览，不会立即写入。可直接修改分类、任务和 checklist 名称，移除分类会把其中的根任务改为未分类，移除任务会连同其子任务一起移除。核对汇总数量后点“创建”，整份草稿才会一次性提交；任一字段或层级不合法时全部回滚，不留下半份计划。重复提交同一份已成功草稿不会重复创建。
- 点击任务行进入只读优先详情：系统导航栏显示任务标题，首个身份行只显示父级路径（根任务显示“根”），不再重复标题或“运行中”；如果任务正在计时，计时状态只由紧接着的明确“停止”动作表达，同区的“添加时间”仍保留。随后是清单、预测、备注，以及异步载入的摘要、分析和近期记录。打开详情时，开始、停止、添加时间和编辑等核心操作会先出现；分析正在计算只在分析区显示加载行，不会以整页转圈阻塞操作。
- 任务详情使用系统返回按钮。返回任务列表后，原来的搜索词和树展开状态会继续保留；在 iPad 或 Mac 侧边栏中打开任务时，同一条任务会保持选中。只有任务被删除或同步结果表明它已不存在时，应用才会自动关闭失效详情。
- 点击铅笔进入完整编辑表单。取消有改动的任务、分类、手工时间或时间片编辑器会要求确认。
- 在 iPhone/iPad 任务编辑器中点“符号与颜色”会进入同一编辑流程的下一页；搜索或选择后点左上角返回，已输入标题和所选外观都会留在草稿中。返回不等于保存，仍需使用外层“保存”提交；“取消”会放弃整份草稿。Mac 上该选择器显示为 popover。
- 任务移动会阻止把任务移入自身、后代或当前不可接收工作的父节点。普通载入与同步刷新不会改写 CloudKit 分阶段送达的层级事实；若暂时缺少父节点或检测到循环，界面投影会先把安全断点显示为根节点，等待后续同步补齐。显式恢复快照时才会规范化异常层级。
- Checklist 是任务内部步骤，不能独立计时。完成项为预测提供证据；更改 checklist 会立即刷新该分支与祖先汇总。
- 任务编辑器可设置 15 分钟步进、最多 10 小时的预计时长。明确预计时长会直接形成当前任务自身的预测；未设置时才回退到 checklist 完成证据与当前任务真实计时。父任务仍会另行汇总子任务预测，不把父任务预计时长误当成整个分支的预算。
- 完成全部 checklist 只表示任务内部步骤已完成，并为进度与预测提供证据；它不会改变任务本身的可工作性、停止现有计时，也不会阻止继续计时、补录、运行番茄钟、编辑任务或使用其后代。
- 只有任务自身或祖先已归档、已删除或不存在时，任务才不能接收新工作或成为新的父任务。归档分支会从日常任务选择器与任务树中隐藏，但历史账本仍保留原归属。
- 任务编辑器保存时会核对打开草稿时的任务、checklist 外观和分类版本。若另一个窗口或同步结果已经修改、删除或新增相关内容，旧草稿会被拒绝，避免覆盖或复活对方的更改。此时可选择“重新载入最新版本”：确认后会丢弃当前未保存草稿，载入最新任务、checklist、分类和父任务候选；也可选择“保留我的草稿”，先复制或核对当前输入，不会自动覆盖新版本。
- 开始计时、快速开始、番茄任务和新建记录的任务选择器统一排除不能接收新工作的任务；已归档、删除或不存在的分支不会成为新工作的目标。历史时间片编辑仍可保留原始任务，不会因为当前不可计时而丢失归属。
- 归档隐藏任务但保留历史。任务或其后代仍在计时时，界面会要求先停止，不能把活动计时器静默藏进归档。删除任务树会先停止该树中的活动计时，并结束活动番茄流程，然后软删除任务；历史账本和番茄记录保留。无论从任务菜单还是滑动操作发起，界面都显示同一份“删除”确认，不使用“软删除”等实现术语。

同名任务可能属于不同路径。开始计时或接受 AI 建议前，应同时核对标题与显示路径。

## 7. 番茄钟

“专注”页把下一次专注与最近记录放在同一工作区：窄屏上下排列，空间足够时左右排列。开始区只保留一个主操作，最近记录用于核对任务路径、状态和完成轮次。

1. 用“计划”菜单选择方案。主操作下方会同时列出专注、短休息、长休息和轮数，避免只看到部分参数。
2. 点“任务”打开可搜索的任务表，按标题或完整路径查找并确认绑定任务；列表显示标题和父级路径，当前选择带勾选。同名任务可用搜索路径区分。这个选择只属于当前“专注”页面，不会自动启动专注、改写任务页或全局当前任务。标题和倒计时不承担隐藏手势。
3. 点击选择器之后的“开始专注”。它会优先保持在 iPhone 浮动标签栏上方；内容较长时仍可把它滚动到完整可点的位置。开始时会创建 `PomodoroRun`、`TimeSession` 和 `TimeSegment`。
4. 专注阶段的 deadline 由持久化的阶段状态与计划时长计算。应用退到后台、被系统挂起或重新启动后，会按同一 deadline 对账，并把专注账本截到计划结束时刻，而不是把挂起时间错误算作专注。
5. 专注结束后进入短休息或长休息。休息中可点“跳过休息”立即开始下一轮；倒计时归零后按钮改为“开始下一轮专注”。两者都需要明确点按，后台不会擅自创建下一段专注。
6. 最后一轮专注结束后，流程完成并结束关联 session。
7. “停止番茄钟”需要确认。非常短且主动取消的首次尝试可能连同记录一起丢弃；已有有效记录的流程会保留历史。

如果绑定任务在休息期间被归档、删除或因祖先变化而不可工作，开始下一轮的按钮会停用；仍可安全停止当前番茄流程。Checklist 完成不会触发这项阻止。继续、完成和停止都固化打开操作时的阶段版本；同一 run 已进入下一阶段、下一轮，或被跨设备替换时，旧按钮/确认框不会误操作新阶段。

VoiceOver 会把阶段、完整任务路径和本地化剩余时长作为一个计时器语义朗读，视觉进度条不会重复播报同一信息。辅助功能大字号下，任务名和路径会增高换行，不以缩小文字通过布局。

编辑仍在运行的番茄时间片会同步重绑任务和阶段起点；把它改为已结束会结束/取消对应 run。删除活动番茄时间片会同时 tombstone 对应 run，避免界面仍显示一个没有账本事实的番茄钟。

## 8. 分析

分析首页显示当前范围摘要，并先把可行动的“决策”和“质量”放在“复盘”区；“深入查看”再提供时间、任务、番茄钟和指标详情。范围以日、周、月三个日历单位选择；选到历史日期后可用“回到今天”直接返回当前周期，并可按参考日期前后移动。

- 连续前后移动“月”范围时，应用会保留开始导航时的本地日号与时分秒。若目标月没有该日，会暂时使用月末，再在较长月份恢复原日号，例如 1 月 31 日 → 2 月 28/29 日 → 3 月 31 日。直接选择日期、切换范围或回到今天会建立新的锚点；进入当前月时会恢复到当前时间。
- 当前范围存在相交的活动计时时，分析会在下一个真实分钟边界刷新；不会因为打开了详情页而重复启动另一套页面时钟。
- 同一日、周或月在刷新时会保留该周期已显示的内容，并在范围控制旁显示轻量进度指示；切换到不同日、周或月则只显示新周期的加载状态，绝不会把旧周期的指标冠以新范围。
- 任务详情在活动计时期间也会更新当前周期指标和最近记录。分析刷新只在 App 前台安排；返回前台、系统时钟或时区改变时会重新核对。应用会在日期范围索引与任务分支索引中选择候选更少的一侧求交集，并另取该分支最近 8 条；不会每分钟重新扫描该任务的全部历史，也不会把所选周期内全 App 的记录都送进任务分析。
- 历史范围和没有相交活动计时的范围不会每 30 秒重算整页。当前静态范围只等待下一个本地日历日；历史范围不保留时钟任务。应用会在回到前台、系统时间或时区改变时重新核对日期，日期跨入下一天/周/月时会切换到新的范围快照。
- 已结束的历史日、周或月会统计到该日历周期的精确结束边界，不会漏掉午夜前最后一秒。仍在运行但跨越所选历史周期的记录只计入该周期内的部分；未来周期在真正开始前保持为空。
- 当前日、周或月的增减值只与上一周期的相同进度比较，例如周四 14:30 对比上周四 14:30；不会拿尚未结束的本周与完整上周比较。跨夏令时仍按本地钟点对齐，长月份超出上一个短月份的日期会对齐到上一个月末。已完成的历史周期则明确与上一个完整周期比较；指标脚注会显示当前采用的口径。没有设置目标值时，增加和减少都只用中性样式陈述变化，不把“少记录”自动标成好事。
- 周/月趋势只显示已经开始的本地日，当前月不会在折线末尾补入未来零值；已完成的历史周期仍显示完整日序。蓝色柱表示合并重叠后的墙钟时间，绿色线表示允许并行计时的累计时间，图例和 VoiceOver 会说明两者；不足一分钟的数据仍按小数分钟参与绘图，不会被截成零。
- 在“我花了多少时间？”中打开“总计与定义”可查看三个口径：Gross Time 会把每个任务计时器全部相加，Wall Time 会把重叠区间合并后只算一次，Overlap Excess 等于 Gross Time 减去 Wall Time。例如任务 A 与任务 B 都在 9:00–9:30 运行时，Gross 为 1 小时、Wall 为 30 分钟、Overlap Excess 为 30 分钟。
- 小时图、任务颜色和选择状态提供 VoiceOver 语义；辅助功能大字体下，范围 segmented control 会改为菜单。
- 预测优先使用当前任务明确填写的预计时长；未填写时由 checklist 完成证据和真实计时驱动。历史 90 个本地日只用于估算“以近期活跃日节奏还需多少天”，不会凭空制造剩余小时。

## 9. 系统入口

### 快捷指令与 Siri

系统可发现“添加收件箱项目”“开始计时”“停止计时”。添加与运行方法：

1. 打开“快捷指令”，新建快捷指令并选择“添加操作”。搜索“时间追踪”或动作名称，再添加需要的动作。
2. “添加收件箱项目”必须填写“标题”；运行后会把文字加入收件箱。
3. “开始计时”必须选择一个当前可计时的任务；同名任务会显示父路径供核对。它遵守“允许并行计时”设置：关闭并行时会先停止冲突计时；该任务已经在计时时不会再创建一条重复计时。
4. “停止计时”要求选择一条当前运行的计时；同名任务会显示父级路径供核对。执行时会固化该时间片 ID，只停止所选计时；目标已经停止或失效时，不会回退去停止另一条。旧版无目标调用只在恰好存在一条活动计时时兼容，并行计时时会拒绝执行。
5. 点按快捷指令中的运行按钮测试；保存后也可以从“快捷指令”、Spotlight 或 Siri 运行。系统提供的短语包括“在时间追踪中添加收件箱项目”“在时间追踪中开始计时”和“在时间追踪中停止计时”等本地化变体。

这些动作在应用未打开时也使用同一原子领域命令。提交成功后，应用会尽力刷新 Widget、Watch 和 Live Activity；投影刷新失败不会把已经保存的动作伪装成失败并诱导重复执行。

若快捷指令尚未出现，先启动一次主应用，再在“快捷指令”中重新搜索。系统可能缓存旧元数据。

### Live Activity

Live Activity 不需要在 App 内手动创建：iPhone 允许 Live Activity 时，开始第一条计时后，应用会在账本刷新时自动请求并维护它；最后一条活动计时停止后会自动结束。它是账本的状态投影，不是唯一事实来源。

并行计时时只维护一个 Live Activity，不会为每条计时分别创建：

1. 最早开始、仍在运行的计时是主项。新鲜状态且普通字号下，锁屏按“任务图标 / 任务标题与任务路径 / 已运行时间”显示，展开的灵动岛只保留“图标 / 任务标题 / 时间”这一行；空间不足或辅助字号使用同一组件自适应，更新延迟时只额外显示状态 glyph。
2. Live Activity 不再堆叠附加计时数量或停止控件。停止主项后，下一条最早开始的活动计时会成为新主项。
3. 点按锁屏或灵动岛会回到“今日”。若要停止计时，请在“今日”的正在计时区域使用对应停止按钮；Live Activity 本身只展示账本投影，不修改数据。
4. 紧凑和最小灵动岛受系统宽度限制：紧凑态显示可截断的任务身份与时间，最小态优先显示受 stale 边界约束的时间——新鲜时更新，进入更新延迟后冻结；任务色 keyline 保留身份线索。

系统可能因权限、低电量和并发数量限制展示或更新。连续活动达到八小时后会标记为“更新延迟”，已用时间停在最后受支持的确认边界，不会让陈旧投影继续增长；主应用中的账本计时不受这个展示边界影响。

如果从 Widget、Live Activity 或系统链接打开时应用仍在准备数据库，合法动作会等到初始化完成后再执行；重复点击同一动作只保留最新一次。无法识别、参数错误或过长的链接会被忽略，不会打开任意页面或绕过任务可计时判定。

### Apple Watch

安装并取得第一次快照：

1. 在 iPhone 的 Watch app 中启用“自动安装 App”，再在配对 iPhone 上安装“时间追踪”。iPhone App 包内包含依赖型 Watch 伴侣，系统会把它安装到满足最低 watchOS 版本的配对手表；若关闭了系统自动安装，可在 Watch app 的“可用 App”中手动安装。
2. 在 iPhone 上打开一次 TimeTracker 主应用，再打开 Watch app。Watch 会先读取手机上次发送的 application context；首次没有快照时会显示“正在等待 iPhone”。
3. 保持 iPhone 与 Watch 在附近，并让 iPhone 主应用完成启动和数据刷新。Watch 收到快照后才显示活动计时与任务；“更新延迟”或“连接出现问题”时也用同样方式让 iPhone 主应用重新刷新。

Watch 使用三张系统纵向分页，旋转数码表冠或上下轻扫可依次切换“正在计时”“快速开始”“所有任务”：

- 第一次收到手机快照时，通常有活动计时就默认打开“正在计时”，否则打开“快速开始”。若此时有命令失败、正在发送或排队、连接错误或快照陈旧等需要处理的状态，即使没有活动计时也会先打开“正在计时”，让恢复入口立即可见。后续才出现的状态或失败不会把你从正在查看的页面拉走；此时“快速开始”和“所有任务”顶部会出现至少 44 pt 高的“查看状态”（英文为“Review”）按钮，点按后回到“正在计时”处理。
- “快速开始”最多显示四个未运行任务：先按手机上的固定顺序放入固定项，再用高频、近期任务补足。这个顺序只属于“快速开始”，不会改变“所有任务”的排序。
- “所有任务”保留正在计时的任务，并按历史时间片数量从多到少、最近开始时间从新到旧排序；完全相同的项目用稳定任务 ID 决定顺序。已归档、删除或不存在而不能接收新工作的任务不会出现；Checklist 是否全部完成不影响显示或开始计时。
- 开始：点按“快速开始”或“所有任务”中尚未运行的任务行。即使已有活动计时，也可以选择另一个任务；iPhone 会在提交时读取全局“允许并行计时”设置，开启时并行开始，关闭时按同一规则切换计时。行尾播放图标会变成沙漏，等待 iPhone 确认期间该行不可重复提交。
- 查看运行项：“所有任务”用行尾绿色计时器图标表示正在运行；点按这类任务会回到“正在计时”页，不会暗中停止它。
- 停止：只在“正在计时”页点按对应计时行。Watch 发送的是该时间片 ID，因此只停止这一条，不会把其它并行计时一起停止。
- 确认：任务与计时行会明确显示空闲、发送中或失败状态；“操作已排队”表示命令已经保存在 Watch 上，等待 iPhone 可连接时传送，不等同于已经在账本中完成。

每个新命令先进入本机持久队列，并使用耐久 `transferUserInfo`；iPhone 当前可达时再用即时消息加速。手机会返回 typed terminal result：成功、重复、任务缺失、时间片缺失、无效、失败或超时。Watch 的“已排队”不表示数据丢失，iPhone 暂时不可达也不等于 CloudKit 或后台传输整体离线。

20 秒未收到 terminal result 时，Watch 会把命令移入可重试状态；重试保留原 command ID 但刷新发送时间，避免已经成功但回执丢失的动作执行两次。手机不会执行已经超过 30 秒的旧命令，防止长时间离线后突然开始或停止计时；这类命令会显示为无效，可在确认当前状态后重试或丢弃。旧版手机只回传快照时，快照反射仍作为兼容确认方式。

“正在计时”页先列命令问题，再列连接、队列或更新状态，最后才列活动计时；恢复信息不会被计时行压到下面。主页只展开第一个命令问题；若有多个，进入“所有待处理操作”逐项处理：

- “重试”沿用原 command ID，只刷新发送时间再传送，避免已经成功但回执丢失的动作执行两次。
- “丢弃”只从 Watch 的失败列表移除这条提示，不会撤销、停止或反转 iPhone 上可能已经完成的操作。因此必须先在 iPhone 核对真实计时；不再需要重发时才丢弃。

命令问题、连接状态和“更新延迟”仍显示在“正在计时”页；陈旧快照中的已用时间会冻结在最后确认值，不会继续伪装成实时计时。手腕放下或 Always On 降低亮度时，任务标题和路径会按系统隐私状态遮盖。

Watch 会拒绝用较旧快照回退当前画面。状态快照最多显示 64 个活动计时和 256 个可工作任务，所有投影文本共用 128 KiB 预算。手机按四级优先级决定哪些任务进入上限：先保留 Watch 快照实际传输的运行任务，再保留新版 Quick Start 固定项，然后保留旧版 Watch 会显示的前四个非运行 legacy Quick rows，最后按使用频率与最近开始时间补足其余名额；重叠任务只保留一次。只有入选集合确定后，才为旧版 Watch 兼容把传输数组重排成原先的 pinned-first 顺序。新版本手机同时发送独立的全任务排序信息，因此“所有任务”仍按使用频率和最近开始时间排序，不按最终兼容数组或固定顺序重排。新 Watch 连接尚未提供该排序信息的旧版手机时，会安全回退到手机原先发送的任务顺序。异常长的标题/路径可能在 Watch 上按完整 Unicode 字符边界缩短，但主 App 的原任务不会被改写。手机 incoming 命令、Watch 待处理和失败列表各最多 64 项，本地队列编码最多 512 KiB，不会因长期离线无限增长。待处理项超过上限时，最旧命令会转成可见失败项而不是静默执行；损坏、重复 ID 或异常大的本机队列会在恢复时被丢弃。出现这类状态时，先核对 iPhone 上的真实计时，再决定重试或丢弃。

### Widget

当前 Widget 只声明小型与中型系统尺寸，不提供 accessory circular、inline 或 rectangular 等锁屏 Widget。添加方法：

1. iPhone/iPad：长按主屏幕空白处进入编辑，选择“添加 Widget”，搜索“时间追踪（Time Tracker）”，选择小型或中型后添加。
2. Mac：按住 Control 点按桌面并选择“编辑 Widget”，搜索“时间追踪（Time Tracker）”，选择小型或中型后放到桌面。
3. 首次添加后先打开一次主应用，让它把最新账本快照写入 App Group；系统决定具体刷新时机，Widget 不是实时账本。

主应用和 Widget 使用 `group.me.mezorewww.timetracker` 中的版本化快照。交互边界如下：

- 点击小组件的非控件背景、正在计时摘要中除停止按钮外的区域，或普通“打开”提示，只会打开“今日”，不会开始或停止任务。
- 小型空状态中，只有带播放图标且明确显示任务名的链接会开始该任务。
- 中型右侧 Quick Start 中，只有具体任务行会开始对应任务。
- 当前计时摘要的 app-opening 控件明确表示“打开 Time Tracker 后停止”。它固化并只停止当前显示的时间片；目标已失效时不会误停其它并行计时。Quick Start 的播放图标仍只表示开始。

Widget 能区分等待快照、共享容器不可用和快照损坏。单个快照最多 256 KiB，活动计时与近期任务各最多 64 项，共用 128 KiB 文本预算。生成快照时会按完整 Unicode 字符边界缩短超长标题/路径，并把统计和异常计时开始裁到安全范围；这只影响 Widget 投影，不改写主账本。非法日期、负统计、重复 ID 或过长文本会被视为损坏快照，不会被当作空账本。发行前仍必须在真实设备验证主应用写入、Widget 读取、timeline reload、主屏幕/桌面和离线状态。

## 10. 设置、AI、同步与数据安全

设置分为：通用、专注、数据与同步、AI 助手、高级。iPhone 设置是从“今日”打开的独立 sheet，关闭后保留原标签和导航；iPad 使用侧边栏目的地，Mac 使用系统 Settings 场景。外观跟随系统，不提供应用级亮/暗覆盖。

辅助功能大字下，设置的标题和输入框会改为纵向排列；VoiceOver 会读出行标题、当前值和同步状态。“清空全部数据”等破坏性动作使用红色文字/图标和系统破坏性语义，但仍应以确认对话文案为准，不要只根据颜色判断影响。

### 倒计时

在“设置 → 通用 → 倒计时”中可以管理跨设备显示的纪念日或截止日期：

1. 点按“添加”创建倒计时；新项目默认使用“新事件”作为标题，并把日期设为七天后。
2. 编辑标题后，点按“保存”、键盘上的 Return，或离开输入框才会提交。仅输入文字不会立即写入数据库或同步到其他设备。
3. 标题不能为空，不能包含换行或控制字符，UTF-8 编码后不能超过 4 KiB。验证失败时会显示行内提示，并保留尚未提交的文字以便修改。
4. 日期调整会立即保存；删除需要再次确认。“今天”倒计时由所有平台共享。

### AI 助手

配置使用草稿工作流：

1. 打开“配置”。输入 endpoint 和 API key 只改变 sheet 内草稿，不会逐字写入偏好或 Keychain。
2. 点击“测试连接”获取模型列表。测试成功不会自动保存凭证。
3. 选择模型后点击“保存”；取消或下拉关闭有改动的草稿会要求确认丢弃。
4. 保存后再明确开启“自动建议”。该开关只保存在当前设备，默认关闭。
5. “编辑任务规划指令”用于调整生成分类、任务和 checklist 时的偏好。指令最多 4 KiB，作为普通偏好参与同步；清空或点按“恢复默认指令”会恢复内置默认值。固定 JSON 格式、数量上限和层级安全规则不可由这段指令覆盖。

API key 存在本机、不可同步的 Keychain；endpoint、模型和模型列表属于可同步普通偏好。远程 endpoint 必须使用 HTTPS；只有严格的本机回环地址允许 HTTP。选择第三方服务表示你授权该服务按其政策处理请求内容和保留数据；发行前必须确认 endpoint 服务方、用途、保留期和删除方式与产品披露一致。

“保存”会先完整检查 endpoint、模型列表和已选模型，再把三项作为一次偏好提交；任一值无效或超限都不会留下其它两项的半成品。API key 属于另一个本机安全存储。若偏好提交失败，应用会尝试恢复保存前的密钥并显示错误，不会把部分成功描述成完整成功。

任务计划只在用户从任务页明确点按“生成”时发送。请求包含当次需求、任务规划指令，以及允许模型使用的图标和颜色列表；它不会上传现有任务库，也不会自动修改、删除或覆盖既有任务。模型结果必须先通过结构、引用、层级、数量和字段校验，再进入本机可编辑预览。

### iCloud

日常查看都在“设置 → 数据与同步 → 同步”：

1. 先读顶部状态卡和“当前存储”。状态卡会区分可用、正在检查、最近的 iCloud 活动、本地模式、需要重启、失败、冲突和临时存储；“当前存储”用于确认本次启动实际连接的是 iCloud 还是本地容器。
2. 点按“检查 iCloud 账户”只确认本设备能否访问你的 iCloud 账户，结果会直接更新在顶部状态卡中。它不会手动触发或等待 CloudKit 导入/导出，也不会选择覆盖方向。
3. CloudKit 导入和导出由系统自动执行。App 在收到完成事件后更新本机视图，因此没有无法保证结果的“立即同步”按钮。
4. 改变“iCloud 同步”开关后，先按状态提示完全关闭并重新打开 App；容器只会在下次启动时切换。

状态卡只把 CloudKit 明确报告完成、且本机刷新与冲突检查也成功的 import、export 或 setup 显示为最近活动；单独收到 remote-store 变更信号不代表某次云操作已经完成。CloudKit 事件失败或后续本机处理失败会显示失败原因，不会先出现绿色成功状态。“检查 iCloud 账户”也只更新账户可用性，不会改写最近活动。

“同步恢复”是覆盖工具，不是日常刷新。没有检测到冲突时，它默认只显示“打开恢复选项”；只有你主动展开后才显示两个覆盖方向。需要恢复时：

1. 若主界面出现非阻断的同步冲突提示，点按“查看副本”进入“设置 → 数据与同步”，再比较“本设备”和“iCloud”两侧摘要；提示本身不会替你选择或覆盖数据。
2. 本设备内容正确时，点按“用本设备替换 iCloud 数据”；iCloud 内容正确时，点按“用 iCloud 替换本设备数据”。
3. 阅读系统确认对话框中的覆盖范围，再点按红色确认按钮；取消不会执行恢复。
4. 按结果提示等待立即处理或完全退出后重启。完成前不要交替选择两个方向，也不要继续录入需要保留的新数据。

自动恢复与显式覆盖是两种不同流程：

- App 因 iCloud 暂时不可用而在本机继续工作、随后重新启用 iCloud 时，会先保护本机分支，再建立新的本机 CloudKit cache。这个自动流程只做比较：本机与完整初始导入相同就直接继续，不同就显示冲突摘要，绝不会在比较前把本机快照静默上传并覆盖云端。
- 如果 App 恰好在一次本机保存完成、恢复快照尚未更新时退出，下次启动会在删除旧 CloudKit cache 前重新打开仍完整的本机 store，并在同一写锁下补抓最新分支；补抓、保护文件或锁失败时会继续保留本机 store，而不是冒险删库。只有你明确选择“用 iCloud 替换本设备数据”时才跳过这次本机补抓。
- 只有你明确确认“用本设备替换 iCloud 数据”时，本机分支才会成为上传赢家；“用 iCloud 替换本设备数据”则会重建本机 cache 并接受云端。两种排队方向互斥，最后一次尚未启动的选择会取代前一次；容器已经进入恢复后，旧设置窗口中的另一方向按钮会被拒绝，必须等当前恢复完成或重启后重新核对。
- 下载或自动比较期间，App 会保持只读，直到同一个新 store 的 CloudKit setup 成功并随后完成首次 import。单独看到“已连接”或 remote-store 通知不代表云端内容已经完整到达。若两侧不一致，只读保护会转为需要选择的冲突，而不是自动解除。
- 恢复中断后，下次启动只复用已经记录 setup 和 initial import 都完成的同一恢复会话；缺少任一回执会重新建立 fresh cache。这样不会把半次导入当成完整云端，也不会永久卡在一个无法证明完成的会话上。

- iCloud 开关只保存在当前设备，改变后需要重新启动才能切换 SwiftData 容器模式。
- 远程变更、CloudKit import/export 完成、启动和回到前台会触发刷新；应用没有常驻 5 秒全量轮询。
- “同步”区只放开关、当前状态与 iCloud 账户检查。“同步恢复”与这些普通操作分开；无冲突时先展开“打开恢复选项”，两个覆盖方向始终使用红色破坏性样式。不要把它们当作普通的“立即同步”按钮。
- 检测到真实冲突时，恢复区会直接显示本机与 iCloud 摘要，并在摘要之后显示两个方向，方便先比较再选择；此时无需再展开恢复选项。
- 当本机与 iCloud 在上次确认同步后都发生变化时，主界面只显示可忽略的冲突提示；“解决同步冲突”区才显示两侧摘要和覆盖方向。App 不会在启动时自动弹出两个破坏性选择。“用本设备替换 iCloud 数据”把当前本机标为权威版本并可能覆盖云端及其他同步设备；“用 iCloud 替换本设备数据”接受云端版本并可能覆盖本机。执行前先比较任务/账本摘要，并确认其他设备已经完成同步。
- 从点按覆盖方向到最终确认之间，如果本机或 iCloud 内容又发生变化，App 会拒绝旧确认并要求重新核对最新摘要。这个提示不是操作失败后的重试按钮；必须重新阅读两侧内容，再选择覆盖方向。
- 若本次启动已回退到本地 store，上传或下载会排到下次启动：按结果提示完全关闭并重新打开 App，让它先清理冲突 cache、重新连接 iCloud，再执行所选方向。不要在等待期间反复交替选择两种方向。
- 若 App 找不到可证明安全的本机上传快照，或无法删除旧 store/同步状态，本次启动不会继续连接 CloudKit，也不会把 pending 恢复标成完成。保留设备与 App 数据，处理存储空间、文件保护或容器错误后再重启；不要反复切换覆盖方向来绕过门控。
- 如果准备下载后无法重新打开 iCloud store，应用会进入只读恢复状态，禁用编辑和计时以免临时修改在下次启动时丢失。iPhone/iPad 可从恢复页打开系统设置，检查 Apple ID、iCloud Drive、网络和可用空间后从 App 切换器关闭并重新打开；Mac 可打开数据文件夹、复制诊断并退出。不要把临时内存恢复界面当成可继续工作的数据库。
- 损坏的同步恢复状态会被隔离；如果主要 SwiftData store 能正常打开，应用会建立新的恢复基线，而不是用损坏文件覆盖主数据。记录提示和发生时间后再继续观察多设备结果。
- CloudKit 可能先送达计时段、稍后才送达对应任务或会话。应用会保留这些暂不完整的原始行，但在关系补齐前不把它们计入今日、分析、Widget 或 Watch；后续同步补齐父记录后会自动恢复显示。不要用“优化数据库”尝试删除这类短暂中间状态。
- 同步状态文件由跨进程文件锁保护；App 与 Shortcuts 同时写入时不会用各自的旧副本互相覆盖。Cloud export 用 epoch、generation 和 event checkpoint 确认准确版本，较旧或乱序回调不能把较新的本机修改误标为已同步。

### JSON 导出

1. 打开“设置 → 数据与同步 → 数据”，点按“导出 JSON”。
2. App 成功读取并序列化当前可同步业务数据后才会打开系统文件导出器；选择可信的文件夹和文件名并保存。
3. 保存成功后，“数据”区会就地显示结果；取消系统文件导出器不是错误。读取、序列化或写入失败时，错误只在当前设置场景显示；处理存储问题后重试，不要把未生成文件误认为空备份。

导出包含可同步业务数据，但过滤 API key 和设备本地开关。当前没有 importer、校验和、加密和事务恢复，因此：

> JSON 导出不是可验证、可恢复的备份。

如果读取或序列化失败，App 会显示错误并留在设置页，不会打开文件选择器，也不会用空对象 `{}` 生成一个看似成功的文件。先处理错误，再重新执行导出。

请只保存到可信位置，不要把包含任务名称和详细时间记录的文件直接上传到公开工单或仓库。

### 手动补录

1. 在任务列表或任务详情中对目标任务选择“添加时间”；也可以在 Today 时间线中选择“添加相似时间”。Mac 还可在主窗口按 `Shift-Command-M`。设置页不承载补录工作流。iPhone/iPad 会直接打开完整高度编辑页，不提供无法完整容纳表单的半高状态。
2. 核对“归属”中的任务。表单会优先使用当前所选、仍可计时的任务，否则选择第一个可用任务。
3. 调整开始和结束时间；新草稿默认是结束于当前时刻的最近 30 分钟。结束必须晚于开始，两者都不能在未来。
4. 可填写备注，然后点按“保存”。没有任务、时间无效或备注不符合持久化规则时，保存按钮不可用或显示错误。提交时会再次检查任务仍可计时；若另一窗口的操作或刚完成的同步已归档或删除该任务，当前草稿不会写入旧归属，刷新后选择可用任务再保存。
5. 取消有改动的草稿时，确认是否丢弃；保存成功后记录会进入同一时间账本和分析，不会启动活动计时。

### 删除与维护

- 清空业务数据的实际入口是“设置 → 高级 → 维护 → 重置数据”。点按后必须在“删除所有数据？”确认对话框中再次选择“删除所有数据”；点按取消不会改动数据。
- 普通 Local、iCloud、local-fallback 和 emergency/in-memory-fallback 生产 store 永不物理清除 tombstone，因为没有每台离线设备的删除确认，过早清除可能让旧设备复活数据。
- 因此生产设置不会显示“永久优化/清理 tombstone”入口；该入口只用于隔离的 Demo/UI Test store。
- “重置数据”是破坏性逻辑删除，并可能经 iCloud 传播；它还会清除本机 Keychain 中的 LLM API key 和设备本地的自动建议同意。它不会替用户切换当前设备的 iCloud 启动开关。执行前必须阅读确认。
- Debug 的演示重建/清除只应在明确使用独立 demo store 时操作。

## 12. 故障排查

### 无法开始或保存

1. 查看当前窗口或场景显示的错误提示，以及“设置 → 数据与同步”的当前存储模式。设置中发起的导出、维护和同步恢复错误只在该设置场景显示，不会跳到另一个主窗口。
2. 如果是临时内存或待恢复模式，先停止录入并重启/修复持久容器。
3. 确认任务及其祖先未归档、删除或丢失；Checklist 全部完成不会阻止计时。再确认开始时间不在未来、结束时间晚于开始且不在未来；“时间记录不能延伸到未来”表示 App 已在写入前拒绝该范围。
4. 如果任务编辑器提示任务已在其他位置更改，表示另一个窗口或同步结果已改动相关任务/checklist/分类。选择“重新载入最新版本”可在当前编辑器继续；该操作会丢弃未保存输入。若要先保留或复制当前内容，选择“保留我的草稿”，不要反复提交同一旧 baseline。

### 启动进入只读恢复页

1. 先停止录入；只读恢复页不会把当前进程中的临时更改当作可持久保存的数据。
2. 点按“复制诊断”可复制状态、错误信息、持久化模式和 store 路径。报告可能包含本机目录与错误详情，发送给他人前先检查并脱敏，不要附 API key、任务内容或未审查的导出文件。
3. Mac 可点“打开数据文件夹”核对文件是否存在，并使用页面上的“退出”完整结束应用；不要手动删除或替换 store。iPhone/iPad 记录诊断后完全关闭 App。
4. 检查可用空间、文件保护、Apple ID、iCloud Drive 和网络，再重新打开。若仍失败，连同 app 版本、build、发生时间和已脱敏诊断寻求支持。

### 数据没有同步

1. 确认设备使用同一 Apple ID、允许 iCloud Drive，并且 TimeTracker 的当前设备开关已开启。
2. 重启应用让容器模式生效，保持前台一段时间，查看账户和持久化模式。
3. 不要连续交替点击“用本设备替换 iCloud 数据”和“用 iCloud 替换本设备数据”。
4. 如出现冲突，先判断哪一侧是权威事实，再选择方向。
5. 若提示操作已排到下次启动或进入只读恢复，完全关闭 App，确认 iCloud 可用后重新打开；恢复完成前不要继续录入。
6. 记录 app 版本、build、设备、时间、所选同步方向和错误信息后再寻求支持；不要附 API key 或未经脱敏的 JSON。

### AI 测试或建议失败

检查 endpoint、API key、模型、网络、额度和服务方状态。远程 HTTP、伪装 loopback、跨源 redirect 和 HTTPS 降级会被安全策略拒绝；服务端超过 60 秒或返回超过 2 MiB 的响应也会明确失败，不会继续占用内存读取。重新编辑凭证后必须再次“测试连接”并保存。自动建议仍需单独开启。

生成任务计划失败时，草稿不会写入任务库。先缩短需求或设置中的任务规划指令，再点“重试”；如果提示重复项目、缺少父项、循环层级或数量过多，表示模型结果没有通过本机校验，应重新生成。创建阶段失败时整份计划会回滚，可继续在预览页修改后再试。

### Watch 命令未确认

打开 iPhone 主应用并保持附近连接，等待 typed result 或新快照。超时后使用“重试”；不要快速重复创建多个新命令。确认手机真实状态后，可丢弃已经不需要的失败项。

### Widget 为空或报错

先打开主应用生成快照，再检查 Widget 的 App Group/profile。共享容器不可用、快照缺失和损坏是不同故障；空状态不表示主应用数据丢失。

### 番茄钟在后台结束

重新打开应用。专注阶段会按持久 phase 状态派生的 deadline 对账并截断账本；休息结束后需要手动点击“开始下一轮专注”，尚未结束时也可明确选择“跳过休息”。如果仍显示不一致，请记录 run 状态、计划时长和实际返回时间。

### Mac 出现多个状态或重复自动请求

当前版本只创建一个主窗口，Settings 与主窗口共享 store。若升级后仍观察到重复行为，完全退出旧构建并重新启动，确认没有另一个安装路径或旧进程仍在运行。
